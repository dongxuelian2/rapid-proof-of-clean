# Research workflow

This workflow keeps infrastructure, evidence, and proposal work separate.

## Phase 0 — Infrastructure / challenge intake

- keep the repository private
- establish environment and CI checks
- record challenge metadata as verified or `TO VERIFY`
- preserve restricted originals outside Git
- create the source and claims ledgers
- do not select a technical direction

## Later phases

1. Challenge intake, rules/IP audit, and broad technology landscape scouting.
2. Evidence-backed feasibility analysis and quantitative modeling.
3. Proposal drafting with claims linked to sources.
4. Review, compliance checks, and submission preparation.

Each phase should add a dated entry to `RESEARCH_LOG.md` and decisions to `DECISION_LOG.md` when a project-level choice is made.
